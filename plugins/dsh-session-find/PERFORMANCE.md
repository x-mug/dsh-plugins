# 性能实测

环境：Ryzen 9 9900X / Windows 11 / Node 24.18，2026-10-29 测量。语料由 `test/benchmark.mjs` 合成，每项预热 1 次，随后测量 11 次取 median / p95；测量期间存在其他集成任务负载。数字为搜索引擎与 Worker 的实测记录，不构成与其他编辑器的对标结论，也不是当前新增全局扫描功能的端到端测试。

## ASCII 语料

| 文本量 | 场景 | 同步查询 median / p95 | Worker 往返 median / p95 | 主线程单次回调 | 主线程最大计时漂移 |
|---|---|---|---|---|---|
| 10 MiB | 忽略大小写、稀疏命中 | 3.55 / 4.12 ms | 18.24 / 34.00 ms | 0.136 ms | 8.22 ms |
| 50 MiB | 忽略大小写、稀疏命中 | 11.80 / 13.36 ms | 29.79 / 36.29 ms | 0.112 ms | 32.33 ms |
| 100 MiB | 忽略大小写、稀疏命中 | 16.36 / 21.60 ms | 47.95 / 113.78 ms | 0.072 ms | 7.97 ms |

## 混合中文 + emoji + ASCII 语料

10 Mi UTF-16 单元（约 17.3 MiB UTF-8，保守按 20 MiB 文本计）：

| 场景 | median / p95 |
|---|---|
| 忽略大小写、稀疏命中 | 1.513 / 3.027 ms |
| 中文、无命中 | 2.304 / 5.231 ms |
| 中文、稠密命中（10 万条上限） | 4.999 / 7.344 ms |
| Worker 往返（稀疏） | 15.30 / 17.81 ms |
| 主线程单次回调 | 0.269 ms |
| 主线程最大计时漂移 | 13.89 ms |

## 内存与负载

- 10 万条紧凑命中索引约 1.2 MB（复用缓冲，无逐条重分配）。
- 首屏 50 条结果约 18–22 KiB（ASCII）/ 约 29 KiB（混合稠密）。
- 翻到最后一页 <0.13 ms。
- 当前会话文本预算按 UTF-16 单元计，默认 64 Mi（保守计 128 MiB），另有主线程文档 Map、Worker 文本副本、折叠缓存和运行时开销；它不是整个浏览器进程的内存硬上限。
- 全局模式保留相同 Worker 匹配引擎，逐批 upsert → query/page → remove，不把所有会话全文同时放进 Worker；主线程最多保留 5,000 个命中及其有界片段。

## 说明

- 匹配在 Worker 内按约 8 ms 分片执行，结果按页回传。主线程仍有 RPC 响应解码、事件文本提取和 UI 更新成本；仅凭后台匹配不能推导真实按键到绘制延迟。
- 上述 Worker 往返含调度与传输开销，因此明显高于同步查询时间。
- 当前会话冷启动先用授权 projections 取得水位，再 page 到零并核对页内及页间连续覆盖。全局模式另有授权目录枚举、逐会话 projections 和 page 成本。本表不包含这些读取成本、React 渲染、实际 Ctrl/Cmd+F 到绘制延迟或旧消息跳转。
- 100 MiB ASCII 含 100 Mi 个 UTF-16 单元，基准显式提高了文本预算；插件默认只接收 64 Mi 个 UTF-16 单元。表中的 MiB 指 ASCII 输入字节，不能当作默认插件容量。
- 当前会话输入有 35 ms 合并等待，增量历史更新有 100 ms 合并等待；全局查询有 150 ms 合并等待，均不包含在表内。全局面板的毫秒值目前只累加各批 Worker 查询耗时，不是目录读取和全量扫描的墙钟耗时。
- `setImmediate` 单次回调和 2 ms interval 的最大计时漂移来自 Node 主线程，在 Worker 查询期间采样；不是浏览器输入延迟或完整 UI 可操作性证据。
- 基准采样的进程 RSS 包含源文档、Worker、V8 预留及前序测量残留；没有测量峰值，也没有测量真实浏览器内存。

## 全局扫描预算与宿主边界

| 默认客户端限制 | 值 |
|---|---:|
| 累计扫描文本 | 128 MiB，按 `text.length × 2` 计 |
| 一轮扫描时限 | 60 秒 |
| 候选会话 / 历史页 | 各最多 10,000 |
| 文本块 | 最多 100,000 |
| 单批文本 | 最多 16 MiB |
| 每页消息请求 / 返回页事件上限 | 50 / 50,000 |
| 保留命中 | 最多 5,000，界面每页 50 条 |

达到限额、读取错误、目录或归档状态变化会保留未完成原因；用户取消会停止后续批次并拒绝迟到结果。正则查询的 1.5 秒、普通 Worker 查询的 5 秒 watchdog 负责中止匹配线程，不负责宿主 RPC 预算。

这些预算属于客户端扫描与批次交付。rc.3 宿主在冷会话 projections/page 中仍可能准备或折叠整份日志，插件没有宿主侧硬 CPU、内存或 I/O 上限；已经开始的宿主任务不一定随客户端取消立即终止。因此目前不能承诺 60 秒内宿主工作全部结束，也没有“所有工作区冷扫描峰值受 128 MiB 限制”的实测结论。

全局扫描分别固定每个会话的水位并验证覆盖，不建立所有会话的同一时刻原子快照。当前未记录新增全局读取路径的真实 Web/Desktop 端到端耗时和峰值；需要与本页已有 Worker 基准分开验收。
