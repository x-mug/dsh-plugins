# 会话查找（@x-mug/dsh-session-find）

面向 DSH 0.2.1-rc.3 的会话查找插件。在当前聊天、输入区或本插件面板中按 `Ctrl+F` / `Cmd+F` 打开查找；可切换“当前会话”和“所有会话”，搜索原始文字与代码子串，并核对来源后定位消息。界面会区分覆盖已核对、扫描中和仅部分结果；未加载到聊天正文的历史也会独立读取。

也可点击会话标题栏搜索按钮，或在命令面板中运行“会话查找”。快捷键服务中的命令默认未绑定按键，可自行设置；插件不提供备用默认组合，避免与宿主快捷键冲突。直接 Ctrl/Cmd+F 由页面监听，只在当前会话的安全作用域处理；文件预览、终端、代码编辑器、模态、菜单及其他输入控件保留自己的行为。若 Desktop 原生层在 DOM 之前接管按键，可通过按钮、命令面板或自定义快捷键打开。

## 为什么需要它

DSH 0.2.1-rc.3 没有独立的“当前会话内查找”：

- 浏览器自带查找只能覆盖已经挂载的消息。旧历史仍分页存放，未加载的消息搜不到。
- 侧栏搜索是跨会话的会话级搜索；内置 SQLite 后端在当前 Desktop 配置里 `openAt: never`，且用 `unicode61` 分词，中文和代码标识符的内部子串无法命中。
- 官方“会话搜索”插件只给 Agent 注册工具，不改变侧栏，也不提供 Ctrl+F。
- 消息跳转没有公开 API；`conversation.openView('chat', focus)` 写入的 `viewRequest` 官方 Chat 并未消费。

本插件不改变内置包，保留独立 Worker 做匹配。当前会话先通过授权的 `remote.session.projections` 获取持久事件水位 `asOfSeq`，再固定 `throughSeq`，用 `remote.session.page` 向前分页到序号零。只有页内序号连续、页间衔接、尾水位及 `hasMore` 均一致，才报告历史覆盖已核对；缺页、重复或错误耗尽会显示部分历史。实时持久事件也检查连续性，重连替换会重新建立覆盖。

“所有会话”复用授权的 `session.list`、`session.projections` 和 `session.page`，按页送入同一搜索 Worker 匹配，读取一批后释放该批全文。范围是授权目录中所有工作区的普通会话，子会话不纳入；归档会话默认排除，可勾选纳入。每个会话各有读取水位，这些水位不是所有会话在同一时刻的原子快照。扫描期间目录或归档状态变化、单会话读取错误和预算中止都会报告未完成原因。

## 功能

- 文本匹配在后台 Worker 执行，主线程负责提取文本、调度及每页 50 条结果显示；不把全文挂入聊天正文。
- 区分大小写、中文等无大小写字符的字面量搜索走原生 `indexOf`；忽略大小写时，ASCII 缓存内走折叠加 `indexOf`，其余走转义后的 `giu` 正则以保留 UTF-16 偏移。
- 选项：区分大小写、全字匹配（Unicode 字母/数字/下划线边界）、正则、包括思考文字。
- 计数、上一个/下一个（`Enter` / `Shift+Enter`）、每页 50 条结果；跨会话结果显示会话标题、工作区和归档标记。
- 新输入取消过期查询（latest-wins）；Worker 正则查询超过 1.5 秒、普通查询超过 5 秒会被中止并重建，病态正则不在宿主执行。全局扫描可主动取消。
- 导航先核对会话、持久序号、角色、文本块及 UTF-16 范围。原文与渲染文字完全一致且 Range 文本再次一致时才精确高亮；Markdown 显示不同、零宽命中或浏览器高亮不可用时，只定位到已核对的消息并提示原因。
- 搜索范围：已完成的用户输入与助手文字；思考可选。工具、附件、注入上下文、compaction 摘要不在范围内。被 compaction 从模型上下文移除、但当前会话仍可见的原始消息仍会被搜到。

## 安装

在 Desktop 的 **插件 → 添加插件 → 安装第三方插件** 里填一段安装地址即可，不需要先手动下载。插件管理器接受 npm 包名、绝对本地路径、git 地址和 http(s) 压缩包直链四种写法。

**A. 仓库地址（推荐，可从标签复现）**

```text
github:x-mug/dsh-plugins#v1.1.0&path:/plugins/dsh-session-find
```

去掉 `#v1.1.0&` 则跟随默认分支。也可以写完整 URL：
`git+https://github.com/x-mug/dsh-plugins.git#v1.1.0&path:/plugins/dsh-session-find`。

**B. Releases 压缩包直链（不下载文件，直接贴地址）**

```text
https://github.com/x-mug/dsh-plugins/releases/download/v1.1.0/local-dsh-session-find-1.1.0.tgz
```

**C. 已下载的压缩包或本机源码目录**

填该文件的绝对路径，或插件目录的绝对路径（例如本仓库的 `plugins/dsh-session-find`）。

安装后重载应用，打开会话并在聊天或输入区按 `Ctrl+F` / `Cmd+F`，点击会话标题栏搜索按钮，或从命令面板运行“会话查找”。快捷键服务中的命令初始未绑定，可自行配置。

升级：先把旧版本移除，再用新版本地址安装。只写仓库根地址 `https://github.com/x-mug/dsh-plugins` 不行——根目录不是插件包，管理器会以“不是插件包”拒绝并回滚。文件链接插件用同样的写法，把路径换成 `plugins/dsh-code-location-links`。

> 安装是否成功以 Desktop 插件页显示的状态为准；本仓库的测试不代替运行中的应用验证。

## 使用与边界

| 场景 | 行为 |
|---|---|
| 旧历史尚未加载 | 插件独立读取并验证分页覆盖，搜索阶段不调用 `loadOlder` / `loadThrough` 挂载正文 |
| 点击当前会话命中 | 校验来源，调用 `loadThrough` 加载目标窗口，再核对 DOM 行及 Range；无法唯一确定来源时拒绝定位 |
| Markdown 显示与原文不同 | 定位到已核对的消息，提示精确高亮不可用；不会按相同字符串猜位置 |
| 点击其他会话命中 | 打开目标会话并重新建立本地索引，核对同一来源命中后再定位；超时或结果变更会终止交接 |
| 归档命中 | 可查看标题和片段；插件不自动取消归档。需先在工作区取消归档再打开定位 |
| 正在流式生成的回复 | 当前会话在持久化完成后增量纳入；全局扫描需重新扫描才能覆盖其水位之后的新回复 |
| 历史超预算或页证明失败 | 保留已读取结果，明确显示“仅部分历史 / 扫描未完成”及原因，不能解释为完整范围无命中 |
| 会话切换 / 关闭查找 | 取消旧任务与导航、释放其 Worker 和全文引用，迟到结果不会写入新会话 |

## 已知限制

- 导航会请求聊天视图并依赖 rc.3 的 Chat DOM 锚点。来源、文本块、挂载会话或锚点不唯一时会停止；DSH 升级后需重新核查兼容性。
- `loadThrough` 在已有普通分页进行中时可能提前返回；插件先等待空闲再加载并校验。跳转旧消息可能让 DSH 挂载目标到当前窗口之间的历史；搜索阶段不触发这项渲染成本。
- 当前会话默认最多 128 MiB UTF-16 文本、100,000 个文本块、100,000 处命中。全局扫描默认累计文本预算 128 MiB、60 秒、10,000 个会话、10,000 页、100,000 个文本块，单批文本最多 16 MiB，每页请求最多 50 条消息，遇到超过 50,000 条事件的返回页会拒绝；最多保留 5,000 处全局命中。达到任何限额即停止并显示未完成原因。文本预算按 `text.length × 2` 计，实际进程内存还包括 Worker、主线程副本、结果片段和运行时开销。
- 这些限制约束客户端扫描与批次交付。rc.3 宿主处理冷会话的 projections/page 时仍可能准备或折叠整份日志；插件没有宿主侧硬 CPU、内存或 I/O 预算。客户端取消和 60 秒时限会停止后续工作、拒绝迟到响应，不能保证已经开始的宿主操作立即结束。
- 当前会话的“历史覆盖已核对”仅证明从零到本次权威水位的连续覆盖，并检查后续收到的持久事件。全局“扫描完成”表示候选会话分别通过页证明，不能表示所有会话在同一时刻的快照；扫描中新产生的消息、目录变化及归档变化需重新扫描。
- 正则使用 JavaScript `g`/`gi` 语义，不支持用户指定额外 flags；查询以单个原始文本块为边界，跨块或跨消息的匹配不计入结果。零宽结果可计数，但没有可高亮的文字。
- 全文和索引只在内存。关闭查找或切换当前会话后释放本地索引；全局每批匹配后移除该批全文，仅保留有上限的命中片段，再查询会重新扫描。
- 首次读取、跨会话扫描和消息跳转的成本不包含在 Worker 查询基准中，见 [PERFORMANCE.md](./PERFORMANCE.md)。本仓库的单元测试和模拟 DOM 测试不等同于真实 Web/Desktop 按键与高亮验收。

## 开发

```powershell
node build.mjs                                    # 生成 client.js 与 test/worker-built.js
node --test --test-isolation=none test/*.test.mjs # 全量测试
node test/benchmark.mjs                           # 性能测量
```

`build.mjs` 把 `src/engine.js` 与 `src/worker.js` 合并成嵌入 Client 的 Worker 文本，并把其余源码组装为 `client.js`；测试前必须先构建。沙箱环境下请使用 `--test-isolation=none`，避免子进程管道被拒绝。

默认跳过两项可选的宿主集成测试：设置 `DSH_TEST_VENDOR_DIR` 指向已解包的 `cordis/`、`cosmokit/` 和 `dsh-client-shortcuts/` 目录后，会额外验证生成的 Client 在 Cordis 4.0.5 中加载与卸载，以及实际 rc.3 快捷键注册器在六种平台配置下的冲突检查。仓库不含任何第三方运行时源码。

打包后可用 `node test/package-check.mjs <tgz>` 逐文件比对归档与工作区内容并输出 SHA256。
